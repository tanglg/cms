# 第一版开发任务拆分

本文档把 `docs/first-version-scope.md` 拆成可独立开发的垂直切片。每个任务都应尽量覆盖数据规则、权限、界面入口和验收条件。当前任务粒度已确认：不需要继续拆细或合并。

任务 2、任务 3、任务 4 需要人工评审，并指定使用 magicpath 技能；其他任务不需要人工评审。

## 任务 1：账号登录与成员管理

**类型**：AFK

**前置依赖**：无

**要实现的内容**

建立第一版个人账号体系。管理者可以创建销售成员账号，账号包含姓名、手机号和初始密码；手机号作为唯一登录标识。用户可以登录、退出和修改自己的密码。管理者可以重置密码、修改手机号、停用账号。同一账号可以同时拥有销售成员和管理者角色。

**验收标准**

- [ ] 用户可以用手机号和密码登录。
- [ ] 手机号全局唯一，重复手机号不能创建或修改成功。
- [ ] 管理者可以创建成员账号，设置姓名、手机号、初始密码和角色。
- [ ] 管理者可以重置成员密码。
- [ ] 用户登录后可以修改自己的密码。
- [ ] 管理者可以停用成员账号；停用账号不能登录。
- [ ] 管理端团队数据包含管理者自己作为销售成员产生的数据。

## 任务 2：销售端移动端交互设计

**类型**：HITL

**前置依赖**：无

**评审方式**：使用 magicpath 技能，由用户亲自评审。

**要实现的内容**

设计销售成员手机端的核心交互流程，覆盖登录、今天列表、客户详情、新建潜在客户、登记客户接触记录、创建计划接触、修改关注程度和修改密码。重点验证销售成员在外出场景中能快速完成登记，首页围绕“今天计划客户”组织，而不是自由流水账入口。

**验收标准**

- [ ] 提供销售端手机尺寸的关键页面设计或可交互原型。
- [ ] 今天列表是销售端首页，默认只展示当天计划客户。
- [ ] 从今天列表到登记客户接触记录的路径清晰，计划客户登记后保留并显示已登记。
- [ ] 从客户详情页可以登记非计划接触记录，但首页不提供自由新增接触记录入口。
- [ ] 新建潜在客户流程只要求客户名称。
- [ ] 登记客户接触记录流程只要求沟通内容，接触时间不可编辑。
- [ ] 登记成功后可以选择创建下一次计划接触，也可以跳过。
- [ ] 登记成功后可以顺手调整关注程度，也可以跳过。
- [ ] 关注程度一到五级在手机端易于识别和修改。
- [ ] 关键手机路径不拥挤，单手操作下主要按钮和输入区域易触达。

## 任务 3：管理端桌面信息架构与列表设计

**类型**：HITL

**前置依赖**：无

**评审方式**：使用 magicpath 技能，由用户亲自评审。

**要实现的内容**

设计管理端桌面优先的信息架构和核心列表体验，覆盖团队今日计划执行、接触记录流、客户列表、客户详情、成员管理、负责人变更、停用/恢复客户和账号管理。重点验证管理者能快速看见计划执行、高关注风险、成员活动和客户推进情况。

**验收标准**

- [ ] 提供管理端桌面尺寸的关键页面设计或可交互原型。
- [ ] 团队今日计划执行能按成员展示计划数、已登记数、未登记数。
- [ ] 四级、五级未登记客户在管理端有明显但不过度干扰的提示。
- [ ] 接触记录流按销售成员分组，成员组和组内记录排序规则清晰可见。
- [ ] 客户列表支持负责人、客户状态、关注程度筛选和客户名称搜索。
- [ ] 客户详情顶部能清楚展示状态、负责人、关注程度和正式客户协议签署日期。
- [ ] 成员管理流程覆盖创建账号、停用账号、重置密码和修改手机号。
- [ ] 负责人变更、客户停用和客户恢复等高影响操作有清楚的确认反馈。
- [ ] 管理端桌面布局适合筛选、扫描和对比，不以营销式大卡片为主。

## 任务 4：第一版视觉规范与响应式验收

**类型**：HITL

**前置依赖**：任务 2、任务 3

**评审方式**：使用 magicpath 技能，由用户亲自评审。

**要实现的内容**

定义第一版的基础视觉规范和响应式验收标准，保证销售端手机体验和管理端桌面体验一致、清晰、可扩展。规范应覆盖基础组件、列表密度、表单、按钮、状态颜色、关注程度展示、空状态、加载状态、错误状态和确认反馈。

**验收标准**

- [ ] 定义基础组件样式：按钮、输入框、文本域、列表项、筛选控件、标签、弹窗或确认层。
- [ ] 定义客户状态、计划状态、关注程度的展示方式。
- [ ] 定义四级、五级关注程度和未登记计划的强调方式。
- [ ] 定义空状态、加载状态、错误状态和提交成功状态。
- [ ] 销售端关键页面在手机视口下文字不溢出、按钮不拥挤、主要操作易触达。
- [ ] 管理端关键页面在桌面视口下筛选、列表和详情信息层级清楚。
- [ ] 手机和桌面都避免信息互相遮挡、布局跳动和不可读的小字。
- [ ] 视觉规范不引入与第一版范围无关的装饰性页面或营销式落地页。

## 任务 5：销售成员创建和查看自己的潜在客户

**类型**：AFK

**前置依赖**：任务 1、任务 2、任务 4

**要实现的内容**

销售成员可以在手机端新建潜在客户，只填写客户名称。创建人自动成为负责人，关注程度默认一级。销售成员可以查看“我的客户”列表、搜索客户名称、进入客户详情，并修改自己负责客户的关注程度。

**验收标准**

- [ ] 销售成员只能新建潜在客户，不能直接新建正式客户。
- [ ] 新建客户只要求客户名称。
- [ ] 客户名称全局唯一，重复名称不能创建成功。
- [ ] 新建潜在客户默认关注程度为一级。
- [ ] 创建人自动成为客户负责人。
- [ ] “我的客户”只显示当前销售成员负责的客户。
- [ ] “我的客户”支持按客户名称搜索。
- [ ] “我的客户”默认按关注程度从高到低排序；同级内从未接触客户排最前，再按最近接触时间升序。
- [ ] 销售端客户详情显示客户名称、客户状态、关注程度、未来计划和历史接触记录，不显示负责人。
- [ ] 销售成员可以修改自己负责客户的关注程度。

## 任务 6：管理端客户治理

**类型**：AFK

**前置依赖**：任务 1、任务 3、任务 4、任务 5

**要实现的内容**

管理者可以查看全团队客户列表和客户详情，创建潜在客户或正式客户，修改客户名称、关注程度和负责人，停用或恢复客户。客户名称在潜在、正式、停用状态中全局唯一。

**验收标准**

- [ ] 管理端客户列表显示全团队客户。
- [ ] 管理端客户列表支持按负责人、客户状态、关注程度筛选，并支持客户名称搜索。
- [ ] 管理端客户列表默认按关注程度从高到低展示。
- [ ] 管理者可以创建潜在客户并指定负责人。
- [ ] 管理者可以创建正式客户并指定负责人；正式客户必须填写协议签署日期。
- [ ] 管理者可以修改客户名称，且新名称必须全局唯一。
- [ ] 管理者可以修改任意客户的关注程度。
- [ ] 管理者可以停用潜在客户或正式客户；停用客户不能新增计划接触或客户接触记录。
- [ ] 管理者可以恢复停用客户；恢复后回到停用前状态，负责人保持不变。
- [ ] 管理端客户详情显示客户名称、客户状态、负责人、关注程度；正式客户显示协议签署日期。

## 任务 7：销售成员创建和维护未来计划接触

**类型**：AFK

**前置依赖**：任务 2、任务 4、任务 5

**要实现的内容**

销售成员可以为自己负责且未停用的客户创建未来计划接触。计划接触只包含客户和计划日期，不包含目的或备注。未来计划可以修改或删除；删除后管理端不可见、不留历史。同一销售成员对同一客户同一天最多只能有一个计划接触。

**验收标准**

- [ ] 销售成员只能给自己负责的客户创建计划接触。
- [ ] 停用客户不能创建计划接触。
- [ ] 计划接触只包含客户和计划日期。
- [ ] 可以为任意未来日期创建计划接触。
- [ ] 同一销售成员对同一客户同一天不能重复创建计划接触。
- [ ] 未来计划可以修改计划日期。
- [ ] 未来计划可以删除，删除后不出现在销售端或管理端。
- [ ] 今天和过去的计划不能由销售成员手动删除。
- [ ] 客户详情页显示未来计划，并按计划日期升序排列。

## 任务 8：销售端今天列表

**类型**：AFK

**前置依赖**：任务 2、任务 4、任务 5、任务 7

**要实现的内容**

销售端首页改为“今天”列表，只显示当前销售成员今天计划接触的客户。列表项展示客户名称和登记客户接触记录按钮，点击客户名称进入客户详情。首页不提供自由新增接触记录后再选客户的入口。

**验收标准**

- [ ] 今天列表只显示当前销售成员今天的计划客户。
- [ ] 今天列表显示当天全部计划，不限制 3 到 7 条。
- [ ] 列表项可以进入客户详情。
- [ ] 列表项提供登记客户接触记录入口。
- [ ] 首页没有“新增接触记录后再选客户”的自由入口。
- [ ] 未登记计划客户排在已登记计划客户前。
- [ ] 各组内按关注程度从高到低排序。
- [ ] 同关注程度内，从未接触过的客户排最前，再按最近接触时间升序。
- [ ] 已登记计划客户当天仍保留在今天列表中并显示已登记。

## 任务 9：提交不可变客户接触记录

**类型**：AFK

**前置依赖**：任务 2、任务 4、任务 5、任务 7、任务 8

**要实现的内容**

销售成员可以为自己负责且未停用的客户提交客户接触记录。记录字段极简：客户、系统接触时间、沟通内容。沟通内容使用固定 placeholder。接触时间为提交时间，不能修改；不支持补录。提交后记录不可编辑、不可删除。填错时只能新增记录说明更正。

**验收标准**

- [ ] 销售成员只能为自己负责且未停用的客户提交客户接触记录。
- [ ] 可以从今天列表的计划客户提交接触记录。
- [ ] 可以从客户详情页提交非计划接触记录。
- [ ] 接触时间由系统记录为提交时间，用户不能编辑。
- [ ] 沟通内容为必填自由文本。
- [ ] 沟通内容 placeholder 为“请填写：接触方式、接触对象、沟通内容、沟通结论。”
- [ ] 接触方式不作为独立字段。
- [ ] 提交后的客户接触记录不能编辑或删除。
- [ ] 当天计划客户提交第一条客户接触记录后，该计划显示为已登记。
- [ ] 同一计划日后续追加客户接触记录不重复增加计划完成数。
- [ ] 签约状态变化不会自动创建客户接触记录，也不会登记计划。
- [ ] 提交成功后提示创建下一次计划接触，但不强制。
- [ ] 提交成功后允许顺手调整关注程度，但不强制。

## 任务 10：潜在客户签约转正式客户

**类型**：AFK

**前置依赖**：任务 5、任务 6

**要实现的内容**

销售成员可以把自己负责的潜在客户登记为已签协议，填写协议签署日期，客户转为正式客户。管理者也可以维护正式客户。签约不自动改变负责人，不自动创建客户接触记录。

**验收标准**

- [ ] 销售成员只能为自己负责的潜在客户登记已签协议。
- [ ] 协议签署日期必填。
- [ ] 合同附件第一版不强制。
- [ ] 登记后客户状态从潜在客户变为正式客户。
- [ ] 签约后负责人不自动变化。
- [ ] 签约不会自动创建客户接触记录。
- [ ] 签约不会让当天计划自动变为已登记。
- [ ] 正式客户仍可以创建计划接触和提交客户接触记录。
- [ ] 正式客户仍保留关注程度。

## 任务 11：负责人变更与成员停用约束

**类型**：AFK

**前置依赖**：任务 1、任务 6、任务 7

**要实现的内容**

管理者可以变更客户负责人。变更后新负责人可以查看客户完整详情和历史接触记录，旧负责人不再拥有该客户完整访问权。负责人变更会删除旧负责人今天及未来的计划接触，过去计划保留。停用销售成员账号前，必须先转交其负责的所有客户。

**验收标准**

- [ ] 只有管理者可以变更客户负责人。
- [ ] 客户始终必须有且只有一个负责人。
- [ ] 负责人变更后，新负责人可以在销售端看到该客户。
- [ ] 负责人变更后，旧负责人不能再在销售端看到该客户详情。
- [ ] 负责人变更不会删除客户历史接触记录。
- [ ] 负责人变更会删除旧负责人今天及未来的计划接触。
- [ ] 负责人变更不会删除过去计划接触。
- [ ] 管理者停用销售成员账号前，如果该成员仍负责客户，系统阻止停用并提示先转交客户。
- [ ] 停用成员不能继续作为客户负责人。

## 任务 12：管理端团队今日计划执行

**类型**：AFK

**前置依赖**：任务 3、任务 4、任务 7、任务 8、任务 9、任务 11

**要实现的内容**

管理者可以查看团队今日计划执行情况：按成员显示今日计划数、已登记数、未登记数，并可查看每个成员的客户列表。支持按历史日期查看。未登记列表优先突出高关注客户。

**验收标准**

- [ ] 管理端按成员展示指定日期的计划数、已登记数、未登记数。
- [ ] 默认查看今天。
- [ ] 可以切换历史日期查看。
- [ ] 已登记只由计划日期当天提交的客户接触记录产生。
- [ ] 签约状态变化不计为已登记。
- [ ] 同一计划日多条客户接触记录只让计划完成数增加一次。
- [ ] 未登记客户优先按关注程度从高到低展示。
- [ ] 四级、五级未登记客户有明显视觉提示。
- [ ] 管理者自己的销售成员数据也包含在团队统计中。

## 任务 13：管理端接触记录流

**类型**：AFK

**前置依赖**：任务 3、任务 4、任务 9

**要实现的内容**

管理者可以查看全团队客户接触记录流，默认按销售成员分组，成员组按最近一条接触记录时间倒序，组内记录按接触时间倒序。支持按客户名称、销售成员和日期筛选，不做沟通内容全文搜索。

**验收标准**

- [ ] 管理者可以看到全团队客户接触记录。
- [ ] 销售成员不能访问全团队接触记录流。
- [ ] 默认按销售成员分组。
- [ ] 成员组按该成员最近一条接触记录时间倒序。
- [ ] 组内记录按接触时间倒序。
- [ ] 支持按客户名称筛选。
- [ ] 支持按销售成员筛选。
- [ ] 支持按日期筛选。
- [ ] 不提供沟通内容全文搜索。

## 任务 14：管理端高关注长期未接触列表

**类型**：AFK

**前置依赖**：任务 3、任务 4、任务 6、任务 9

**要实现的内容**

管理端提供一个简单列表，显示四级、五级客户中最近 7 个自然日没有客户接触记录的客户。从未接触过的四级、五级客户也进入列表，并在同关注等级内排最前。

**验收标准**

- [ ] 只显示关注程度为四级或五级的客户。
- [ ] 使用自然日计算最近 7 天，不使用精确 168 小时。
- [ ] 最近 7 个自然日没有客户接触记录的客户进入列表。
- [ ] 从未接触过的四级、五级客户进入列表。
- [ ] 默认按关注程度从高到低排序。
- [ ] 同关注程度内，从未接触过的客户排最前。
- [ ] 同关注程度内，已接触客户按最近接触时间从旧到新排序。

## 任务 15：第一版权限与非范围回归检查

**类型**：AFK

**前置依赖**：任务 1 至任务 14

**要实现的内容**

对第一版范围做一次端到端回归检查，确保权限边界、不可变记录、停用状态、排序规则和明确不做范围都没有被前面任务破坏。

**验收标准**

- [ ] 销售成员不能查看或操作非本人负责客户。
- [ ] 销售成员不能给非本人负责客户创建计划或提交接触记录。
